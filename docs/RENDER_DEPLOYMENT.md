# Render mock-only evaluator

## Status and scope

The repository contains a Render Blueprint for a **public mock-only evaluator**.
It is not a production payment-monitoring service and is **not deployed yet**.
The deployment uses the existing Docker image and approval-service application
factory. The public root redirects to `/evaluator`. Visitors can run only the
three fixed synthetic scenarios and retrieve their persisted execution
evidence. The scenario runner uses AgentSentinel's validated trace collector,
contextual trajectory feature, and existing deterministic rule detector. Its
mock tools access only fixed in-process fixture data.

The evaluator records each request ID, synthetic tool calls and outputs,
detection result, bounded permission decision, timestamps, and linked audit
events in SQLite. Anonymous reads are limited to evaluator results. Only
`POST /evaluator/executions` is allowed to create a scenario; every other
non-GET request is denied in public demo mode. Operator dashboard and approval
API reads remain authenticated. FastAPI API documentation is disabled.

The scenarios never create approvals, change the persistent kill switch,
invoke a payment adapter, or contact PayPal. The displayed outcomes are
simulated only, not live activity or PayPal transactions.

## Render configuration

[`render.yaml`](../render.yaml) specifies one Docker Web Service on Render's
Free plan, linked to `main`, with auto-deploy disabled and `/ready` as its
health-check path. It creates no database, persistent disk, or other paid
resource. Review the Blueprint in Render before applying it.

The container binds to `0.0.0.0` and uses Render's `PORT` value (defaulting to
8000 for local Docker). Render terminates HTTPS; the Blueprint enables Secure
cookies explicitly. `/health` is liveness; `/ready` verifies the initialized
approval-store kill-switch row and the internally configured approver secret.
Neither endpoint verifies PayPal connectivity or external persistence.

## Environment variables

| Variable | Requirement | Purpose |
|---|---|---|
| `APPROVER_SECRET` | Required; generated by the Blueprint | Internal readiness and session-signing configuration. It is not disclosed to site visitors. Public operator routes remain inaccessible. |
| `APPROVAL_DB_PATH` | Blueprint sets `/tmp/agentsentinel/approval.sqlite` | Ephemeral local SQLite initialization for readiness. |
| `AGENTSENTINEL_EVALUATOR_DB_PATH` | Blueprint sets `/tmp/agentsentinel/evaluator.sqlite` | Ephemeral store for bounded scenario execution evidence. |
| `AGENTSENTINEL_PUBLIC_DEMO` | Blueprint sets `true` | Exposes the scenario evaluator anonymously and blocks every write except the fixed scenario-run endpoint. |
| `AGENTSENTINEL_SECURE_COOKIES` | Blueprint sets `true` | Marks dashboard cookies Secure for HTTPS hosting. |
| `PORT` | Supplied by Render; do not set manually | Port for Uvicorn's `0.0.0.0` listener. |
| `DASHBOARD_VIEWER_SECRET` | Not needed | The only anonymous page is the restricted synthetic walkthrough. |
| `PAYPAL_ENVIRONMENT`, `PAYPAL_CLIENT_ID`, `PAYPAL_CLIENT_SECRET`, `PAYPAL_MERCHANT_ID`, `PAYPAL_ACCESS_TOKEN` | Not needed; do not configure | No PayPal integration or credentials are used by this service. |
| Ollama settings or model files | Not needed | The hosted evaluator does not invoke Ollama or download models. |

Never put credentials in the repository or provide them in chat. Do not copy
`APPROVER_SECRET` into public configuration or share it with evaluator users.

## Persistence and cost

The evaluator requires writable SQLite files while it is running, but no
cross-restart retention. The approval database and execution-evidence database
are explicitly placed under `/tmp`; they are initialized on startup and may be
lost at any restart, deploy, or idle spin-down. Executions contain only
predefined synthetic values. No user-supplied payment instructions, customer
records, or payment records are retained. The Free plan does not support a
persistent disk, so this configuration makes no persistence claim.

As checked against Render's current documentation on 2026-11-12, Free web
services are $0, share a workspace allowance of 750 Free instance hours per
calendar month, and spin down after 15 minutes without inbound traffic. A
spun-down service can take time to wake. Free services use an ephemeral
filesystem and cannot attach a persistent disk. These limitations are suitable
only for evaluation, not production availability or data retention. The
Blueprint does not request or enable paid services.

## Manual deployment steps

Deployment cannot be completed from this workspace: the Render CLI and an
authorized Render deployment connection are unavailable, and these repository
changes have not been pushed. No deployment URL exists yet.

After reviewing and publishing the changes to the existing `main` branch:

1. In Render, choose **New → Blueprint** and connect
   `prasanna14200/AgentObservability`.
2. Select branch `main` and the repository-root `render.yaml`; review that it
   proposes only the Free Web Service in this file, with no disk or paid
   resource, then apply the Blueprint.
3. Confirm Render generates `APPROVER_SECRET` as a secret and retains the
   configured environment variables. Do not add any `PAYPAL_*` variable.
4. Wait for the Docker build and `/ready` health check. Open the Render
   assigned `onrender.com` URL and verify it redirects to `/evaluator`.
5. Confirm the page is labeled `Synthetic demonstration — no real payments or
   PayPal actions.` Run each predefined scenario and reload the recent-run list
   to retrieve its evidence. Check `/health` and `/ready`; verify an
   unauthenticated dashboard overview is denied and only the evaluator scenario
   POST is accepted.
6. Copy the actual service URL from Render only after a successful deployment
   and these checks. Do not infer or pre-announce a URL.

Automatic deploys are disabled in the Blueprint. A later deployment requires
an explicit manual deploy or a reviewed change to this setting.

## Local verification

From the repository root, build the same image with:

```powershell
docker build --platform linux/amd64 -t agentsentinel-mock-evaluator -f Dockerfile .
```

Run the full test suite with:

```powershell
python -m pytest -o addopts= -q
```

Docker build and local container smoke success do not establish a successful
Render deployment.
